# Публикуване на Spark на безплатен сървър + отделна администрация

> Тук е описано какво е подготвено в кода и как се пуска. Самото публикуване изисква **твой** акаунт при хостинг (понякога и карта за проверка) – аз не мога да го направя вместо теб.

## Архитектура

```
Интернет ──► Caddy (HTTPS) ──┬─► web    (APP_MODE=public)  spark.example.com        ── spark.db (volume data) + снимки
                             └─► admin  (APP_MODE=admin)   admin-xxxxxx.example.com ── admin.db (volume admin-data, САМО тук)
                                                             + spark.db (data) + backups (САМО тук и в „backup“)
              backup (на 6 ч.) ──► volume backups
```

| Какво | Публичен сайт | Администрация |
|---|---|---|
| Адрес / порт | `SITE_DOMAIN`, 3100 | отделен `ADMIN_DOMAIN`, 3200 (по подразбиране само 127.0.0.1) |
| Маршрути | без `/api/admin*` (404) | само `/api/admin*`, вход, `/api/me`, `/api/meta` (всичко друго 404) |
| Бисквитка | `spark.sid` | `spark.admin`, `SameSite=Strict`, 30 мин. без действие, макс. 8 ч. |
| Акаунти и сесии | `spark.db` | **`admin.db`** (отделен файл/волюм; публичният процес не го отваря) |
| Вход | потребител + парола | парола + **код от приложение (TOTP)**, заключване след 5 грешки, кодът е за еднократна употреба |
| Необратими действия | – | изтриване/дерегистрация: нов 2FA код, **резервно копие преди действието**, най-много 10 на час |

### Какво дава пробив в…
- **публичния сайт (напр. XSS/SQL инжекция/RCE в контейнера):** няма админ API, няма админ парола/сесии (те са в друг файл/волюм), няма достъп до резервните копия (друг волюм). Може да се повреди публичната база → възстановяваш от копие.
- **откраднат админ парола:** без текущия 2FA код не може да влезе. 
- **откраднат админ вход (сесия/код):** за изтриване иска нов код; не повече от 10 изтривания на час; преди всяко се прави копие → щетите са ограничени и обратими.
- Не е защитено от: пълно превземане на **цялата машина** (root), компрометиран телефон с 2FA + паролата едновременно. За това – ограничи достъпа до админ адреса по IP / VPN / Cloudflare Access.

## Безплатен сървър – честно

SQLite файлът и качените снимки трябва да са на **постоянен диск**. Затова:

| Вариант | Подходящ ли е | Бележка |
|---|---|---|
| **Oracle Cloud „Always Free“ виртуална машина** | ✅ най-добър | Истински Linux сървър, диск остава. Иска карта за проверка. Неактивни безплатни машини може да бъдат изтрити от Oracle – ползвай я и пази копия извън нея. Провери актуалните условия. |
| Render / Koyeb / Railway (безплатен план) | ❌ за сегашния код | Файловата система се изчиства при рестарт/„заспиване“ → губиш базата и снимките. Би изисквало Postgres (напр. Neon/Supabase) + хранилище за снимки (S3/R2) и пренаписване на кода. |
| GitHub Pages | само демото | Статично, без сървър (това е демо версията). |

HTTPS иска име (домейн). Безплатно: поддомейн от DuckDNS (напр. `spark-ab12.duckdns.org` и `admin-ab12.duckdns.org`). С платен домейн (~10 €/г.) на Cloudflare можеш да сложиш админ адреса зад **Cloudflare Access** (безплатно до 50 души) – допълнителна врата преди изобщо да стигне до входа.

## Стъпки (Oracle Always Free + Docker)

> Бърз път: след стъпка 1 (VM + портове) пусни на сървъра `deploy/bootstrap.sh` – той върши стъпки 2–5 (Docker, ufw, клониране, тайни в `.env`, `docker compose up`). Още не е изпробван на реална машина. Стъпки 6–7 (админ + 2FA) остават ръчни.

1. Създай VM (Ubuntu 22.04/24.04), отвори портове **80 и 443** в Security List **и** във ufw/iptables на машината. Вход по SSH само с ключ.
2. `sudo apt update && sudo apt install -y docker.io docker-compose-v2 git ufw && sudo usermod -aG docker $USER` (излез и влез пак).
3. `git clone -b claude/add-spark-dating https://github.com/dimitarbeograd-QA/portfolio-demos && cd portfolio-demos/spark-dating/deploy`
4. `cp .env.example .env` и попълни: домейни, `SESSION_SECRET`, `ADMIN_SESSION_SECRET` (`openssl rand -hex 48`, **различни**), `SMTP_URL` (безплатна SMTP поща, напр. Brevo), по желание `ADMIN_ALLOW_IPS` = твоят IP.
5. `docker compose --env-file .env up -d --build`
6. Първи администратор (иска терминал):  
   `docker compose --env-file .env run --rm -it admin node scripts/create-admin.js ТвоетоИме`  
   → въвеждаш парола (14+ знака, скрито) и получаваш **ключ за 2FA** – добави го в Google Authenticator/Aegis/1Password. Показва се само веднъж.
7. Отвори `https://ADMIN_DOMAIN` → вход с потребител, парола и код.

Отнемане на достъп на администратор: изтрий реда му от `admin.db` (сесиите му веднага стават невалидни).

## Резервни копия и възстановяване

- Контейнерът `backup` прави консистентно копие на всеки 6 ч. (последните 28), админът – допълнително преди всяко необратимо действие (`…-pre-erase_user.db`).
- **Копирай ги извън машината** (напр. ръчно седмично с `scp`/`rclone` към друг облак/компютър) – копие на същия диск не помага при загуба на диска.
- Възстановяване:  
  `docker compose stop web admin`  
  `docker compose run --rm --entrypoint sh backup -c 'ls /backups; rm -f /data/spark.db-wal /data/spark.db-shm; cp /backups/ИМЕТО.db /data/spark.db'`  
  `docker compose start web admin`

## Допълнителни защити в кода
Строг CSP, HSTS, `Permissions-Policy`, COOP/CORP; CSRF проверка на Origin/Sec-Fetch-Site; ограничаване на заявките по IP (общо, при вход/регистрация, при качване); заключване при грешни пароли; пароли до 72 байта и без най-честите слаби; сигурностен журнал (виждаш го в админ панела); `nodemailer` е на версия без известни уязвимости (`npm audit` – 0).
Препоръки извън кода: автоматични обновявания на ОС (`unattended-upgrades`), `fail2ban` за SSH, Cloudflare пред сайта (DDoS), редовно `docker compose build --pull`.
